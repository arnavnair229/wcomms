# Ideas borrowed and ideas pending, from kunchenguid's repos

Surveyed 2026-11-27: github.com/kunchenguid (firstmate, no-mistakes, lavish-axi, gnhf, axi, treehouse, backpass,
quota-axi, compact-adviser, tasks-axi, kun, vision, headless, runner-up, gh-axi, whathappened, gsh, baby-menu).
What wforge took, what it deliberately did not, and what is worth building next.

| From | Idea | Where it landed |

## Deliberately not taken

- **A fleet of separate interactive sessions in tmux** (firstmate). Each crewmate is a whole Claude Code process on the
  subscription window. wforge's point is to fan out inside one session with pinned tiers and a cap.
- **Auto-merge** (`+yolo`, no-mistakes' PR pipeline). wcomms' rule: coordination only, merges and deploys are the user's.
- **Multi-harness support**. wforge is a Claude Code plugin by design; the hooks and workflows are Claude Code APIs.
- **Public relay to X or Discord**. Out of scope for a budget tool.

## Worth building next (ranked)

1. **Push gate, wcomms-side** (no-mistakes). A `pre-push` hook that runs `wforge:review-changes` on the branch and
   refuses the push until the skeptic's confirmed problems are empty or the user overrides. Keeps the "never merge"
   rule and still catches slop before it reaches the hub. Half a day.
2. **Memory gradient** (backpass). A monthly `/wforge:backpass` that reads this machine's own Claude Code transcripts
   under `~/.claude/projects/<repo>/`, finds rules that were stated twice or more, and proposes CLAUDE.md edits with
   quotes as evidence. Human-gated like stow. One to two days; the transcript format is JSONL already.
3. **Worktree pool** (treehouse). Claude Code's `isolation: worktree` creates a fresh worktree per builder, so node_modules
   and build caches are cold every time. A pool of warm worktrees reused across crew runs would make M tasks noticeably
   faster. Needs a `wforge-pool` script and a builder instruction to `cd` into one. One day.
4. **Vision doc** (vision). A scout-only workflow that mines `git log` for the repo's direction and drafts a VISION.md,
   then the skeptic stress-tests it. Cheap: haiku plus one sonnet pass.
5. **Headless Mac setup** (headless). A skill that sets up a spare Mac as the nightshift runner over SSH. Only matters
   once nightshift is used weekly.
6. **Repo digest** (whathappened, gh-axi). `/wforge:whathappened` summarising PRs, issues and CI since the user last
   looked, through `gh` on haiku. Overlaps with wcomms' hub view; build only if the hub does not grow it.
7. **AXI-shaped outputs everywhere** (axi). wforge-crew already prints short lines. Audit wforge-usage and the
   workflows' return objects for token cost; drop fields nobody reads.

## Not worth it for this stack

- lavish-axi (HTML review UI): Claude Code has Artifacts.
- runner-up (self-hosted CI runners), gsh (generative shell), baby-menu (menu bar app): different problems.
- kun (a person's distilled opinions as a skill): interesting format, nothing to generalise here.
